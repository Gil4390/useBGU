Keywords — MLM-USE & CatMLM

This grammar has two kinds of keyword. A hard keyword is a bare quoted literal in the grammar (e.g. 'end'); under ANTLR3's testLiterals mechanism, any such literal is auto-promoted to a token reserved everywhere the shared lexer applies — it can never be used as an ordinary identifier anywhere in that composed grammar, even far from the one rule that actually needs it. A soft (contextual) keyword is the deliberate alternative: an ordinary IDENT token that a semantic predicate reclassifies as a keyword only at one specific grammar position, of the shape: 

keyXxx:
  {input.LT(1).getText().equals("xxx")}? IDENT ;

This lets the word remain usable as an ordinary identifier (a class name, attribute name, powerclass name, ...) everywhere else in the language. Counted below: 69 hard keywords and 21 soft keywords, confirmed by extracting every quoted literal (hard) and every keyXxx semantic-predicate rule (soft) from USEBase.gpart, OCLBase.gpart, SoilBase.gpart, and CatMLM.gpart — the grammar for ordinary .use / .mlm specification files. (Scope note: this excludes the separate interactive shell-command grammar — ShellCommandBase.gpart, TestSuite.gpart, Generator.gpart — which is not covered here.)

Hard (fully reserved) keywords — 69

These can never be used as an ordinary identifier anywhere in their composed grammar, in any context, even one unrelated to where the keyword is actually meaningful.

Note on roles: this one did not start as a soft keyword. It was originally a bare ANTLR3 literal in the clabject rule, which auto-promotes to a keyword reserved everywhere in the composed grammar — silently breaking any plain USE model that used "roles" as an ordinary identifier (e.g. an OCL operation parameter), including use-gui's own ShellIT / t109.use integration fixture. Fixed by converting it to a proper soft keyword, matching the pattern already used for role, union, and association.

Confirmed empirically: a plain, single-level model with an attribute named clabject (or mediator, assoclink, or MLM) failed to parse before this fix (mismatched input 'clabject' expecting 'end'). Fixed the same way as roles. clabject and MLM were bare literals in CatMLM.gpart too, independently of USEBase.gpart — since CatMLM is a separately-composed grammar with its own lexer, both files needed the fix; CatMLM.gpart's rules now simply reuse the keyMLM/ keyClabject rules defined once in USEBase.gpart, the same way they already reused keyClass and keyAssociation.

Note on category: an earlier version of the grammar also accepted an optional category hint right after the colon in a clabject declaration (clabject C : category A, B end). It was removed: the < vs : already unambiguously distinguishes same-level generalization from cross-level instantiation, so the keyword added no information the symbol didn't already carry — and it was never actually checked against the named class's own declaration anyway. category is now recognized in exactly one place: the classifier-declaration choice above.

Related, but neither hard nor soft

OCL's query-expression names (select, reject, collect, exists, forAll, isUnique, sortedBy, one, any, collectNested, …) use a different predicate — ParserHelper.isQueryIdent(input.LT(1)) in OCLBase.gpart — to decide whether an identifier immediately followed by ( should build a query-call AST node instead of a plain operation-call one. Unlike every keyword above, none of these names are ever reserved in any sense: they remain fully usable as ordinary operation names everywhere, including in that exact position. The predicate only chooses which kind of AST node to build, never whether parsing succeeds.
